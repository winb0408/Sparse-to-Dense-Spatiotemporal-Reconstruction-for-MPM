## 冻结结论（数字来源：`results/runs_e011/*/summary.json`，per-fold，fold0=测 M1、fold1=测 M2、fold2=测 M3）

| 臂 | 输入行占比 | 监督信号 | PSNR | Dice | clDice |
| --- | --- | --- | --- | --- | --- |
| S1 | 50%（全部采集行） | 密集真值 | 30.46 / 28.92 / 31.98 | .848/.917/.892 | .824/.883/.869 |
| S1h | 25%（与 SS1 完全相同的行） | 密集真值 | 30.13 / 28.83 / 31.90 | .832/.914/.887 | .808/.880/.865 |
| SS1 | 25% | 另 25% 的**测量值** | 23.50 / 24.78 / 24.60 | .677/.830/.753 | .629/.715/.707 |
| SS1c | 25%×2（双分支互补） | 互补测量值 | 24.65 / 24.70 / 26.89 | .663/.817/.766 | .581/.706/.704 |
| SS1c+agree | 同上 + 一致性项 | 互补测量值 | 26.08 / 25.38 / 28.20 | .654/.832/.785 | .583/.751/.729 |

四条冻结结论：

1. **差距的来源是"目标密度"，不是"输入多少"。** S1h 把有监督臂的输入砍到和 SS1 一模一样的
   25%，在它看到的那 25% 体素上确实变差了（−4.82 dB，三折同号），但在需要推断的
   50% 体素上只差 −0.10 dB（落在 1 dB 噪声底线内）。所以"自监督少了 50% 真实值"这一
   指责不成立；成立的是"自监督的目标本身比真值弱"。
2. **双分支互补 + 一致性项（E012b）确实有效**：相对 SS1 提升 +2.26 dB，三折同号（+++），
   分支坍缩被修好（两分支 Dice 0.86/0.30 → 0.040/0.042 的差异消失）。
3. **但 dB 不转化为结构指标**：SS1c+agree 的 Dice 相对 SS1 只动 +0.003。原因是拓扑：
   参考血管图有 1972 个连通域，S1 还原 1391 个，SS1 只有 27 个，SS1c+agree 只有 35 个；
   自监督臂把血管糊成几块大斑，PSNR 上去了，血管树没回来。这正是主线改用骨架/连通性
   评估的直接动因。
4. **自监督臂不保留自己拿到的输入**：有监督臂只有 0.7–1.9% 的平方误差落在"已经给它的
   体素"上，自监督臂是 37–44%。`split_psnr`（`spur_mpm/metrics/image_metrics.py`）就是为
   看清这一点加的，主线的定量评估继续用它，因为它把"抄输入"和"真推断"分开了。

## 复活方式

代码仍在 git 历史里（本目录的 `configs/`、`scripts/` 是 `git mv` 过来的，
`git log --follow <path>` 可追）。模型侧的自监督实现（MMS 损失、互补分支、泄漏检查）
在冻结时的最后一次提交里完整可读：`git show <freeze-commit>:spur_mpm/ssl/mms.py` 等。
若将来重启该项目，建议直接以 E012b 的结论为起点（互补双分支 + 一致性项），
不要重复 E003/E009 的扫参。

**保留在主线里的共享件**：`spur_mpm/ssl/holdout.py`（`HoldoutSpec` / `split_holdout`）不是
自监督专有——它是"从采集掩码里再留出一半行"的通用掩码工具，有监督的同输入对照仍会用到，
所以留在包内，位置见 `docs/CODE_MAP.md`。
