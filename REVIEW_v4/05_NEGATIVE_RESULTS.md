据；没有一条是"感觉不行"，都是预注册判读或可复算的配对差。

## 这些否证怎么处理进论文

- N1/N2 是**必须主动写**的：把它们放在结果节，配上"容量/干扰"归因和两阶段训练作为
  future work，比被审稿人问出来要好得多。U15 的绝对性能（33.4–34.6 dB 三 regime）
  本身足以支撑"一套权重覆盖三协议"的工程主张。
- N4/N5/N6 是**架构选择的正当代价**：证据链（全层 3D → 轻量适配器 → 关掉物理先验
  通道即崩溃）完整，写法是"我们用三轮实验证明轴向耦合应由物理先验承载"。
- N7/N8/N9 是**先验设计的边界**：它们反过来支撑 C3（先验好≠网络好）的论述。
- N3 是**协议设计结论**：新采样几何必须在训练集出现，这直接影响"可扩展性"的表述。
- N10/N11 是**适用域声明**：把主张限定在轴向稀疏，避免"通用物理先验"的过度声明。

## 已知的实现/记录瑕疵（不影响结论，但需在复现说明里写）

1. **config 里 `sigma_z_px = 0.0`**：统一模型（mixed）run 的顶层 regime 记为 `2d`，
   导致 config 写入 0.0，而训练时每个 2.5D 采样点实际用 `--psf_z 1.5`。已实证该差
   异对 query 平面 PSNR 不敏感（33.7829 vs 33.7831），且 EXP-025/026 全部 reval 用
   同一约定、val/test 吻合，结论不受影响。未来 run 应显式记录逐点 PSF。
2. **`(8,2)` 只有 seed0**：主矩阵其余点均有 3 seed。已在所有表中标注。
3. **EXP-022 首轮队列脚本缺陷**：36 行里 18 行重复被跳过，实际只跑了 18 个唯一
   run；巡检发现后补齐。最终 36/36 完整，已在日志记录。
4. **EXP-026 的执行事故**：他人 26 GB 进程三次挤爆 GPU3，3 个 run 在 step 450 OOM
   （当时无 checkpoint-resume），全部重跑。该事故直接催生了 EXP-028 前落地的
   checkpoint-resume（DEC-027 C）。
